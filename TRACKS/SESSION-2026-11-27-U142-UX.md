## Part B — defects to fix in this round

### B1. The car's page overflows to the right (both cars)
`WebPage.h` landscape rule gives `.side` a fixed basis
(`flex:0 0 clamp(84px,24vw,170px)`) and lays each row out with
`justify-content:space-between`, but the landscape `.side span` rule drops
`min-width:0` / `overflow:hidden`, which the portrait rule has. A long SSID, a
long `IP :` value or a `REPLY=` string therefore grows past the column instead of
ellipsising.
**Fix:** keep the column basis, but make every landscape row clip and ellipsise
(`min-width:0`, `overflow:hidden`, `text-overflow:ellipsis`, `white-space:nowrap`,
and let the `<b>` shrink). Same edit in both cars so they stay clones.

### B2. Speed slider alignment (both cars)
`.range-wrap` is `display:flex` with a `34px` thumb, a `.val` of `min-width:44px`
and a `.lim` of `min-width:26px`; in landscape `.range-wrap{margin:0}` while its
track keeps `flex:1`. The track therefore starts under the value column and the
thumb visually overhangs the track ends (a 34 px thumb on a 10 px track without
matching horizontal padding).
**Fix:** give the track side padding equal to half the thumb so the thumb centre
stays inside the track, align the value/limit columns on one baseline, and pin the
row to the same vertical rhythm as the pads. Both cars.

### B3. D-pad position in landscape (both cars)
Today (S-16) each pad owns its half and sits at that half's OUTER edge
(`.pads{justify-content:space-between}` + side padding).
**Open question for the owner — this is a deliberate earlier ruling, so it is NOT
changed without a word:** "standard D-pad position for the thumbs" can mean
(a) keep the outer-edge placement (S-16, current) or (b) return to the centred
crosses. This round leaves it as-is and asks; changing it back would undo S-16.

### B4. 4WD4M "connects once, then doesn't respond" (4WD4M only)
Root cause found and fixed in this round's firmware work (U-142): `hasClient()`
can latch after the phone leaves, so `connected()` never went false, the own AP
stayed parked and the hard-restart watchdog never fired. The liveness proof is now
TX progress (`BT_SPP_TX_STALL_MS`). **Bench verification only** — see
`DEVICE-TESTS.md` U-142-2/3.

## Part C — app changes (separate repo)

### C1. Disconnect button placement
Requested: left side, fixed, immediately right of Back. Today the single
`remote-disconnect` control sits in the header's RIGHT cluster beside
`ModeChooser` and the speed strip. **Fix:** move it into the left cluster, after
the Back control, and keep it fixed there (it must not scroll with the card body).

### C2. The connectivity panel's "dull" controls
Today `secondLinkRefused = linkCap === false && btLive !== wifiConnected` disables
the paused method's connect action. That is correct behaviour but it presents as a
dead control with no way forward. **Fix:** keep the refusal, but pair it with the
one action that ends the pause (disconnect the link that owns it), so the panel
never shows a disabled button with no exit. `describeLinkOwner()` already names
which radio is paused (added this round).

### C3. Prompt on a drop
`reconnectDue` / `handleReconnectConfirm` / `handleReconnectPromptCancel` already
exist in the hub. **Verify** it appears pronto and offers reconnect / cancel /
back; do not add a second prompt.

### C4. Speed slider alignment (app)
Verify the header `ValueStrip` and the remote deck's slider share one alignment
and one value scale with the car's page (`SPEED_MIN..SPEED_MAX`, step).
